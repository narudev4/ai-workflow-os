# Vision

## 背景

出発点は「Codexの出力が日によって悪い」と捉えるのではなく、作業ログ、AGENTS.md、Skill、テンプレートを改善して、自分専用のAI作業環境を育てるという発想です。

ただし、毎タスク終了時にログを全部分析して AGENTS.md を書き換えるところから始めると、ルール肥大化と自動化先行に陥ります。

このリポジトリでは順番を変えます。

1. 仕事の情報構造を定義する
2. 1案件で GitHub 正本化を試す
3. Sheets をクライアント向けビューにする
4. タスク完了条件を明確にする
5. その後に Hook / JSONL / Skill 改善を入れる

## 目指す状態

AIごとの性能や調子に依存するのではなく、案件情報と業務手順が構造化され、どのAIでも必要な文脈を読める状態を作る。

```text
人間
  -> AIとの壁打ち
  -> 構造化された成果物
  -> GitHub正本
  -> Sheets表示
  -> クライアント確認
  -> 実装
  -> ログ分析
  -> テンプレート・Skill・AGENTS改善
```

## 成功の定義

- 要求整理からテストケースまでの成果物が GitHub に残る
- クライアントには従来どおり Sheets で共有できる
- 変更理由が `decisions/` に残り、後から追える
- 長いAIセッションでも、成果物単位で作業境界を切れる
- 改善対象が「モデルの気分」ではなく「環境・手順・テンプレート」になる
